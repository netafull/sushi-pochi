# 回転寿司ポチ

スシロー・くら寿司・はま寿司・かっぱ寿司の**期間限定ネタ・フェア商品**を1日1回巡回して記録し、
販売が終わって公式サイトから消えても記録が残るアーカイブにするサイト（公開予定 https://sushi.netaful.jp/ ）。
価格・カロリー・アレルゲン・販売期間を、あとから引ける形で残す。

姉妹サイト [電書ポチ](https://book.netaful.jp/)・[家電ポチ](https://kaden.netaful.jp/)・
[林檎ポチ](https://apple.netaful.jp/)・[漫画ポチ](https://manga.netaful.jp/)・
[コンビニポチ](https://conbini.netaful.jp/)・[ファストフードポチ](https://fastfood.netaful.jp/)・
[カフェポチ](https://cafe.netaful.jp/)と同じ作り。**構造は `cafe-pochi` の汎用エンジン**（保存スキーマ・終了判定・歯止め・価格履歴・
run_summary/_health・ntfy通知・サイト生成・RSS・sitemap・広告枠のJS・ネタフル記事のひも付け）を引き継ぎ、
チェーン固有の取得を4社分に作り直した。アレルゲン（はま寿司はカロリーも）は公式PDFから読み取る
（`fastfood-pochi` の設計を移植。pdfminer.six だけがpip依存）。
サイトの色は藍系 `#1E3A5F`（ダークモードは `#8FB4E3`）。広告(AdSense)とGA4は config の値が空の間は何も出力しない
（`adsense_client_id` / `adsense_ad_slot` / `ga_measurement_id` は**最初は空**）。

**状態: ローカルだけで作成済み。GitHubリポジトリ・push・DNS・Cloud Scheduler・Secret は未設定**（運営者の確認後に行う）。

## 使い方

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-pdf.txt   # PDFを読むときだけ。.venv/ は gitignore 済み
.venv/bin/python scripts/crawl.py            # 全チェーンを巡回して data/products/ に蓄積(PDFの読み取りも)
.venv/bin/python scripts/crawl.py hamazushi  # チェーンを指定すると、そのチェーンだけ巡回する
.venv/bin/python scripts/fetch_netaful_reviews.py   # ネタフルの記事を取得・商品とひも付け
.venv/bin/python scripts/generate_site.py    # docs/ 一式を生成
python3 -m unittest discover -s tests        # 合成フィクスチャでテスト(公式データのコピーは使わない。data/ docs/ には書かない)
```

素の `python3` で crawl.py を実行しても動く（pdfminer が無いので、PDFの読み取りだけを警告つきで飛ばす）。
取得したPDFは `.cache/pdf/`（gitignore済み）に残り、HEADの指紋が同じ間は再取得しない。

定期実行は `.github/workflows/update.yml`（workflow_dispatchのみ。scheduleもpushトリガーも無い）を Cloud Scheduler から起動する前提
（ジョブ名の案 `sushi-pochi-update`、毎朝1回）。workflow は pip で pdfminer を入れる（失敗しても続行）。
通知の `NTFY_TOPIC` は GitHub Secrets（コードに書かない・**未設定のまま＝通知なし**）。一時停止は リポジトリ変数 `NTFY_PAUSED=true`。
**開発中は本番サイトを必要最小限しか叩かない。**

## 規約上の方針（最重要）

**4社とも規約が複製・転載を禁じているため、記録・表示するのは事実だけ。**

- 保存・表示する: 商品名・価格（税込）・販売期間/発売日・記録開始日・終了（観測）日・カロリー・アレルゲン・公式ページへのリンク。
- **保存も表示もしない: 説明文・画像・画像URL。** パーサは説明文・画像のキーを読み取りもしない
  （テストで確認している）。くら寿司のフェア判定だけは、商品画像のファイル名を「判定の手がかりとして」読むが、値は保存しない。
  PDFの表そのものも保存しない（サイトで記録している商品に名前が一致した行の値だけを入れる）。
- 各商品ページに「出典：○○公式サイト（取得日）」と公式ページへのリンクを付ける。aboutに「事実だけ記録・説明文と画像は載せていない」と書いてある。
- 取得は**素のUA**（`SushiPochi/1.0 (+https://sushi.netaful.jp/)`。ブラウザ偽装はしない）。リクエスト間隔は2秒（コードの下限は1秒）、
  チェーンごとに1回の実行の上限（`max_requests_per_run`: スシロー20・くら寿司20・はま寿司25・かっぱ寿司20。PDFのHEAD/GETも数える）。
  ブロック（403/429・チャレンジページ）されたら**回避せず**そのチェーンを止めて `blocked` に記録する。
  robots.txt は各ホストで1回取り、Disallowは守る（404やHTMLを返すサイトは全許可）。
- 規約の確認結果: スシロー `/about/` は非商業・個人利用で複製禁止（robots.txt は404）。くら寿司 `/policy/` は著作権法で認められる範囲外のコピー禁止
  （robots.txt は404でHTML）。はま寿司 `/aboutsite/` は私的使用を超える転載禁止（robots.txt は対象パス制限なし）。
  かっぱ寿司は規約ページを特定できていない（トップのフッターにリンクが無い。`/info/` は403なので触らない）。robots.txt は `/master_data/` を禁止していない。

### 価格は店舗で違う

- **サイト全体（ヘッダー・トップ・フッター・about）と各商品ページに、「価格は公式サイトの表示（スシローは特定の1店舗）の値。店舗により異なる」と明記している。**
- スシロー: 代表1店舗（config の `sushiro.s_id`、既定 **434＝巣本店・大阪府門真市**）の店舗別メニューの価格。同じ品でも店舗で違う（110円と140円など）。
- くら寿司: 公式メニューの標準の表示（［一皿110円〜店舗］の区分。115・125・145円の店舗区分は別PDFで、このHTMLには出ない）。
- はま寿司: 公式メニューの全国の税込価格（「100円（税込110円）」→110円）。一部店舗・北海道などでは価格が異なる。
- かっぱ寿司: 公式メニューデータの店内の税込（`sell_price_tax10per`）を主に、持ち帰り（`sell_price_tax`）を併記。店内飲食限定の品は店内のみ。

## 何を記録するか

- **初回から、その時点で期間限定・フェアとして載っている商品を全部記録する**。`data/baseline_ids.json` は「初回に見えた記録対象のID」を持ち、
  **2回目以降の歯止めの判定にだけ使う**。
- 商品1件1ファイル `data/products/{sushiro|kurasushi|hamazushi|kappasushi}/{id}.json`。既存ファイルは丸ごと上書きしない（初回取得が正）。
  更新するのは last_seen_at / status / price_history 等の追跡項目と、まだ空のカロリー・アレルゲン・発売日、販売期間の注記（公式の最新の表示）だけ。

### 販売状況の追跡（サイトの核。カフェポチと同じ）

- 巡回で一覧に居たら `last_seen_at` を更新し `status=on_sale`。価格が前回と違えば `price_history` に追記。
- **そのチェーンの一覧取得が全部成功した回だけ**、一覧から消えた商品を数える。取得失敗・0件（構造変更の疑い）・robots.txtでDisallow・歯止めの保留の回は数えない。
- **別の日に連続2回**見つからなかったら `status=ended`、`ended_observed_at` にその日付。同じ日に何度実行しても1回と数える。
- 終了後に再登場したら `on_sale` に戻し、`relaunches` に記録、昨季の期間を `seasons` に残し、今季の発売日は未確定に戻す。
- **終了日は公式発表の最終販売日ではなく「公式の一覧から消えたことを確認した日」**。サイト上にもそう書いている。
  **例外: かっぱ寿司**は公式データに終了日(close_date)があるので、記録済みの商品がその日を過ぎたら一覧から消えるのを待たずにその日で終了にする（`ended_basis=official_close_date`。サイトにもそう表示）。
- **歯止め（burst guard）**: 回転寿司はフェアが2週間前後で丸ごと入れ替わる（スシロー2026-10-28は13品中10品が一度に新規、くら寿司は約50品が1つのフェア）ので、
  カフェポチより緩い。保留にするのは「一覧のほぼ全部(95%超)が一度に新規」か、チェーンごとの絶対数（スシロー40・くら寿司100・はま寿司70・かっぱ寿司60）を超えたとき
  （くら寿司の画像名の規則が変わる・はま寿司のアンカーが変わるなど、記録対象の判定が崩れて通常メニューまで限定扱いになったケースを想定）。
  保留中は新規を記録せず終了判定もしない（`pending.json` の `_suspected_restructure`）。3日連続で通知が「要判断」に変わる。初回は対象外。
  **一覧の全品が一度に入れ替わった日は保留になり、運営者が baseline を更新する必要がある**（既知の限界）。
- **記録対象の急減の検知**（`data/list_state.json`）: 記録対象が前回の半分未満（前回8件以上のとき）に減ったら、3日続くまで終了判定をしない。
- `data/run_summary.json`（gitに入れない）と `pending.json` の `_health` で、ブロック・一覧の失敗・例外・連続日数を `notify.py`（ntfy）に伝える。

## 取得元

### スシロー (www.akindo-sushiro.co.jp)

- 店舗別メニュー `/menu/menu_detail/?s_id=434`（静的HTML。219品目。PC用・SP用で各品が2回出るので `data-target` で重複を除く）。
  各品目が「国産ほたて貝柱 1貫 110円(税込) 38kcal [10/28(水)～11/8(日) 但し販売予定総数343万食が完売次第終了。]」の形。
- **記録対象 ＝ 注記の先頭に `[M/D(曜)～…]` の期間が付いた品目**（2026-11-03は13品。10/28の新作10品＋10/21開始のポムポムプリンコラボ3品）。
  期間の年は曜日が合う年に補う（`resolve_month_day`）。終了日が無い注記（コラボ）は「完売次第終了」だけを表示。販売予定総数（「343万食」）も事実として残す。

- お知らせ `/news/`（1リクエスト）は、見出しの『商品名』と照合して**公式のお知らせへのリンク**を付けるだけに使う（発売日は注記の期間を優先）。
- アレルゲン: 公式PDF `https://www3.akindo-sushiro.co.jp/pdf/menu/allergy.pdf`（16頁、499行、28品目。●＝使用／○＝工場で製造ラインを共有。更新日「2026/10/22更新」）。

## 公式PDFの読み取り（アレルゲン・はま寿司のカロリー）

`scripts/pdf_geometry.py`（pdfminer.six で文字と座標を取り出す。fastfood-pochi の `extract_geometry` を移したもの）、
`scripts/pdf_tables.py`（座標から表を組み立てる純粋関数。4社の設定 `SPECS`）、`scripts/pdf_update.py`（取得・更新検知・検証・反映）。巡回のあとに1チェーンにつき1回走る。

- **表の読み取り**: 1行1メニュー・列がアレルゲン品目の表。見出しは縦書きで1文字ずつ分割される（スシロー・はま寿司・くら寿司）か横書きのラベル（かっぱ寿司）。
  見出しの文字のxで列を作り、メニュー名と同じ高さにある記号を一番近い列に割り当てる。「⻨」など NFKC で直らない部首の字は変換表で直す。
- **照合は名前の完全一致**（NFKC・空白と記号を除く）。ゆるめるのは「先頭の（注記）」「末尾の1貫・（一貫）」までで、曖昧な部分一致はしない。
  同名で記号が違う行が複数あれば採用しない。一致しない商品は「公式PDFでご確認ください」とPDFへのリンクを出す。
- **更新検知**: PDFは毎回は取らない。HEAD（ETag・Last-Modified・Content-Length）の指紋が前回と同じで、未取得の商品もなければ取らない。
  指紋が取れないPDFは7日ごとに取り直す。この版で試して一致しなかった商品は `pdf_tried` に版を覚えて、同じ版では再試行しない。
- **検証ゲート**（`validate_table`）: 表が見つからない・行が少ない・列数が想定外・必須の品目（卵・小麦・えび・かに）の列が無い・記号の読み取り率が低い・更新日が無い・
  （はま寿司）カロリーの列が読めない、のときは**何も更新せず**、`pending.json` に `pdf:allergen` を記録して続行する。読めなかったのと同じ指紋は取り直さない。
  同じ版（更新日）の間は一度入れた値を上書きしない。版が変わったら入れ替えて `allergen_changes` / `nutrition_changes` に残す。
- 403・429・チャレンジ（PDFのはずがHTML）は回避せずその回のPDF取得を打ち切る。pdfminer が無ければ警告を出して飛ばす（巡回全体は止めない）。
- 版の表示: スシロー「更新」、はま寿司「更新」、くら寿司「現在」、かっぱ寿司「確認」の日付を商品ページのアレルゲンの出典に出す。

## 既知の限界

- **フェアの判定が公式の構造に依存する**: くら寿司は画像名の `fair`（今は見出しのセクションが無い）、スシローは `[期間]` の注記、はま寿司は `anchor-limited`、
  かっぱ寿司は「期間限定ネタ」カテゴリ。公式が構造を変えると記録対象が崩れる（急減の検知・歯止めが止めるが、運営者の確認が要る）。
- くら寿司の `fair` 画像は、以前から出ている商品（くらポテト、ハッシュドポテト、せんべい等。画像名の日付が `260626` など古い）も含む。
  公式がフェア扱いにしているものとして記録するが、「今回のフェアの新作」とは限らない。発売日が取れないので、それらも記録開始日から表示される。
- スシロー以外の「代表店舗」は無い（くら寿司・はま寿司は公式の標準・全国の表示）。スシローは1店舗の価格なので、他店舗とずれる。
- はま寿司の地域限定は記録していない。
- 名前が一致しないPDFの行（かっぱ寿司の「ごち寿司…」、くら寿司の「みなみまぐろ中とろ(一貫)」など）は、アレルゲンを載せずPDFへのリンクで案内する。
- スシローの発売日は注記の期間の開始日で、実際の発売日と1日ずれることがある。「完売次第終了」で予定より早く終わる。
- PDFのホスト（`images.zensho.co.jp` など）の robots.txt は見ていない（公式サイトからリンクされた公開PDFを、HEAD+GETの1回だけ取得する）。
- 一覧の全品が一度に入れ替わった日は歯止めで保留になる（上記）。
